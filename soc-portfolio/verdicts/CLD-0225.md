# CLD-0225: Blocked attempts from contained infrastructure: 192.0.2.146

Engagement: Cloudora · Shift 7 · 2026-09-02
Verdict: True positive · Severity (my rating): Informational (reported Medium)
QA review: Excellent

## Alert
Watchlist detection identified 11 sign-in attempts across four Cloudora accounts between 03:10–05:11 UTC on Oct 13 from 192.0.2.146 and 192.0.2.203, both associated with the ongoing Bexley incident. Conditional Access blocked all attempts before password evaluation.

## Hypothesis
Malicious: Known Bexley threat infrastructure was being reused to attempt access to Cloudora accounts after incident containment.

Benign: The connections originated from legitimate users or services coincidentally using the watchlisted IPs.

## Evidence checked
KQL Query 2 — Check the targeted accounts for surrounding sign-in activity

signin
| where Timestamp between (datetime(2026-10-13 00:00:00) .. datetime(2026-10-13 09:00:00))
| where User in (
    "daniel.reeve@cloudora.io",
    "ewalsh.ext@cloudora.io",
    "marcus.oje@cloudora.io",
    "hr-manager@cloudora.io"
)
| project Timestamp, User, IP, Location, Client, Device, MFA, Result, Notes
| order by Timestamp asc

Purpose: Determine whether any of the targeted accounts had successful authentication or suspicious follow-on sign-in activity around the CLD-0225 window.

Result: The query showed the alert-related attempts with no successful authentication identified.

KQL Query 3 — Check for follow-on audit activity

| where TimeGenerated between (datetime(2026-10-13 00:00:00) .. datetime(2026-10-13 09:00:00))

    "daniel.reeve@cloudora.io",

Purpose: Determine whether the blocked attempts were followed by account changes or other audit activity involving the targeted users.

Result: No rows returned. No follow-on audit activity was identified in the searched window.

## Action
Maintain the Conditional Access incident blocks on 192.0.2.146 and 192.0.2.203. Continue monitoring daniel.reeve, ewalsh.ext, marcus.oje, and hr-manager for successful authentication or follow-on activity. Continue monitoring the known Bexley IOCs for attempts against additional accounts or use of new infrastructure. Flag the continued post-containment attempts to the vCISO as threat intelligence. Re-escalate if an attempt reaches password evaluation/authentication, succeeds, bypasses the existing CA controls, or produces follow-on activity.

## Justification
CLD-0225 is a True Positive / Informational because the activity originated from known malicious Bexley infrastructure but was completely blocked by Conditional Access before password evaluation, with no successful authentication or follow-on impact identified.
