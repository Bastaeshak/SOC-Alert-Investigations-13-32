# CLD-0223: Anomalous session: daniel.reeve@cloudora.io, token from new infrastructure

Engagement: Cloudora · Shift 6 · 2026-08-31
Verdict: Escalate · Severity (my rating): High (reported High)
QA review: Excellent

## Alert
Anomalous token use on daniel.reeve@cloudora.io at 2026-10-10 05:52:31 UTC. The account authenticated successfully from 192.0.2.146, an unknown hosting IP on the standing watchlist, using a token with MFA recorded as “Claim satisfied no prompt.”

## Hypothesis
Malicious hypothesis: Daniel’s session token was captured through the phishing portal from CLD-0222 and replayed by the attacker from 192.0.2.146, bypassing the need for an interactive MFA prompt.

Benign hypothesis: Daniel legitimately reused a valid session token from new infrastructure. This is contradicted by the watchlist IOC, unknown hosting source, lack of MFA prompt, Daniel’s normal London/registered-device baseline, and the malicious mailbox activity that followed six minutes later.

## Evidence checked
Queried Daniel’s sign-in baseline, the compromise window, token-related sign-ins, and proxy telemetry.

signin
| where User =~ "daniel.reeve@cloudora.io"
| order by Timestamp asc

Baseline showed Daniel’s legitimate activity from 203.0.113.10, London, using a registered Windows device. Earlier Lagos activity was blocked. 192.0.2.146 is not part of his normal baseline.

signin
| where User =~ "daniel.reeve@cloudora.io"
| where Timestamp between (datetime(2026-10-09 21:36:08) .. datetime(2026-10-12 07:41:19))
| order by Timestamp asc

This showed:

05:52:31 UTC - Success (token) from 192.0.2.146, MFA Claim satisfied no prompt
05:58:44 UTC - active OWA session from the same IP, creating inbox rule . in CLD-0221
07:41:19 UTC Monday - Daniel’s next legitimate sign-in from London on his registered device
signin
| where Result contains "token"
   or MFA contains "no prompt"
| order by Timestamp asc

This confirmed Daniel’s anomalous token event. A separate Marcus token exchange was observed but from normal-looking London/registered infrastructure and was not attributed to this incident.

proxy
| where tostring(pack_all()) contains "daniel.reeve"
| order by timestamp asc

Proxy telemetry showed Daniel accessing 192.0.2.203 at 2026-10-09 21:36:08 UTC, 22 minutes after the CLD-0222 internal phishing email.

## Action
Escalated to the vCISO immediately because the successful authentication involved standing watchlist IP 192.0.2.146. Keep the incident open pending containment and scope confirmation. Revoke Daniel’s active sessions/tokens, contain the compromised account, preserve authentication and mailbox evidence, and review Daniel’s mailbox activity during the compromise window for additional attacker actions or data access. Continue scoping the watchlist infrastructure across available telemetry.

## Justification
Investigation correlated signin and proxy telemetry with related incidents CLD-0222 and CLD-0221.

In proxy, Daniel Reeve was searched for activity associated with the phishing destination. At 2026-10-09 21:36:08 UTC, daniel.reeve accessed 192.0.2.203 using an HTTP GET. The proxy record states the portal was accessed 22 minutes after the CLD-0222 internal phishing email was delivered.

In signin, all activity for daniel.reeve@cloudora.io was reviewed to establish his baseline and investigate activity following the click. At 2026-10-10 05:52:31 UTC, the account recorded Success (token) from 192.0.2.146, classified as Unknown (hosting) using Windows/Chrome. MFA was recorded as Claim satisfied no prompt. 192.0.2.146 is a standing watchlist IOC and is not part of Daniel's observed legitimate baseline.

At 2026-10-10 05:58:44 UTC, six minutes after the token authentication, signin recorded an active OWA session for Daniel from the same 192.0.2.146 source, with the note inbox rule '.' created CLD-0221. This provides confirmed downstream impact from the anomalous session.

Daniel's next observed legitimate authentication occurred at 2026-10-12 07:41:19 UTC from 203.0.113.10, London, using a registered Windows device with MFA satisfied. A subsequent attempt from 192.0.2.146 at 2026-10-13 03:10:27 UTC was blocked by Conditional Access after incident controls were active.

Token/MFA scoping across signin also returned a Marcus Oje token exchange from normal-looking London/registered infrastructure. That event was not attributed to CLD-0223 because the available evidence does not establish that it represents the same token-replay activity.

The sequence that can be independently retraced is therefore: Daniel accesses 192.0.2.203 at 21:36:08 → successful token authentication from 192.0.2.146 with no MFA prompt at 05:52:31 → active OWA session from the same IOC creates the CLD-0221 inbox rule at 05:58:44. This strongly supports successful session-token replay followed by authenticated mailbox manipulation. The successful authentication from a standing watchlist IOC also independently meets the Shift 6 immediate escalation requirement. Verdict: Escalate. Severity: High.

## Tuning note
No tuning recommended. The rule correctly identified anomalous token use consistent with session replay.
